# Изображения, персональные данные и данные разработки

## Загрузка изображений

Сервер принимает JPEG, PNG, WebP и статические GIF. Расширение и MIME-тип клиента
не считаются доказательством формата: файл полностью декодируется Pillow.
Ограничения: 10 МиБ входных данных, 16 мегапикселей, 8192 пикселя по стороне.
Повреждённые файлы, HTML/SVG и анимация отклоняются до обращения к S3.

EXIF-ориентация применяется к пикселям. В хранилище попадает новое изображение без
EXIF, GPS, ICC-профиля и исходных дополнительных блоков. Обычные файлы сохраняются
как WebP с quality=88. Фиксированный объект «Общая.png» остаётся настоящим PNG.
Права загрузки/удаления и папки владельцев аватаров сохраняются. Остальные папки
ограничены известными разделами сайта. Фронтенд показывает ошибки проверки сервера.

Добавлена зависимость `Pillow==13.0.0` (Python >=3.11, совместима с Dockerfile проекта).
Нужно переустановить requirements / пересобрать backend перед внедрением.
Существующие файлы в MinIO этим изменением не переписываются и не очищаются.
S3 в тестах подменяется; реальная загрузка в MinIO в этой среде не проверялась.

## Публичные отзывы

Если у автора нет email, публичное имя — «Пользователь», а не телефон.
Полный email, как и прежде, доступен только администратору. Нового поля публичного
имени и миграции пользователей в этом изменении нет.

## SQL и резервные копии

В обоих прежних дампах были аккаунты, хеши паролей, токены, сеансы и другие реальные
записи. Текущие `database/init.sql` и `backend/database/init.sql` заменены одинаковой
очищенной схемой из более свежего дампа. Сохранена только история миграций Django;
строк прикладных таблиц в них нет. Работающие базы не очищались.

Восстанавливайте эти SQL **только в отдельную пустую базу**: они содержат DROP TABLE.
После восстановления выполните из `backend/app`:

```sh
../venv/bin/python manage.py migrate --noinput
../venv/bin/python manage.py seed_demo
```

`seed_demo` повторяемо добавляет вымышленных актёра, режиссёра, спектакль, премьеру,
показ, состав и отзыв. Аккаунт `demo-viewer@example.invalid` не имеет рабочего пароля
и прав администратора. Для локальной админки используйте `createsuperuser`.
Если миграции уже отмечены выполненными в импортированной схеме, их начальные
контентные данные не создаются повторно — демонстрационные записи добавляет команда.

Скрипты `database/create_dump.sh` и `.bat` теперь создают приватный архив pg_dump
в ignored-каталоге `backups/`, а не перезаписывают отслеживаемый init.sql. Пятый
аргумент позволяет выбрать каталог. Формат custom восстанавливается через
`pg_restore`, не через `psql`. На Linux права новых файлов ограничены через umask 077.
Шаблоны *.dump, *.backup и *.sql.gz исключены из Git. Windows-скрипт в Linux не запускался.

**История Git не переписана.** Старые версии SQL могут по-прежнему содержать записи.
Не восстанавливайте их для разработки. Удаление таких объектов из истории и
пересмотр раскрытых учётных данных — отдельная операция; это изменение её не выполняет.
Рабочая база этой среды сохранена, а очищенная схема проверена в отдельной временной
базе PostgreSQL с последующим применением миграций и повторным запуском seed_demo.

## Запросы спектаклей

Публичный список, административный список и детальная карточка предварительно
загружают режиссёра, показы и состав с актёрами/режиссёрами. Для текущих 17 спектаклей
публичный список выполняет 4 SQL-запроса вместо ранее измеренных 88. Формат ответа
и содержимое карточек сохранены. Тест проверяет, что число запросов не растёт при
увеличении числа спектаклей и участников состава.
