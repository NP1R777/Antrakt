# Превью ссылок и canonical

Публичные страницы получают Open Graph в исходном HTML, а не только после запуска
React. Робот VK, мессенджер и обычный браузер получают один и тот же HTML: User-Agent
не используется для выбора ответа.

## Что отдаётся

- `title`, description, canonical без query/tracking и фрагментов;
- `og:title`, `og:description`, `og:image`, `og:url`, `og:type`, `og:site_name`, `og:locale`;
- Twitter Card с теми же данными;
- новости: type=article, название/описание/картинка опубликованной записи;
- спектакли и проекты: текущая запись, её текст и постер;
- актёры, режиссёры, достижения и основные разделы тоже имеют метаданные;
- пустой/неподходящий URL картинки заменяется абсолютной ссылкой на локальный
  брендированный logo512.png (не на SVG-заглушку и не на приватное хранилище).

Описания очищаются от HTML/script/style и сокращаются до 180 символов. Значения
экранируются; встроенный JSON защищён от закрытия script. Изображения по ссылкам
backend не скачивает. Доступность конкретного постера из Интернета нужно проверить
при развёртывании: адрес в БД должен быть публичным HTTP/HTTPS URL.

Черновики новостей и удалённые записи не отдаются даже администратору через этот
публичный механизм. Нет персональных данных профиля в превью. Админка, профиль
и восстановление пароля имеют noindex без canonical. Неизвестные/отсутствующие
публичные страницы — настоящий HTTP 404 с React-оболочкой и noindex.

## Схема production

1. Caddy по-прежнему передаёт сайт в frontend nginx, sitemap/robots — в Django.
2. nginx отдаёт JS/CSS/изображения как статические файлы, а страницы передаёт в
   `backend:8000/public-page/<путь>`. Cookie/Authorization туда не передаются.
3. Django берёт публичные данные по ID и получает готовый frontend `index.html`
   по фиксированному `PUBLIC_SPA_INDEX_URL=http://frontend/index.html`.
4. Точный nginx location `/index.html` отдаёт файл напрямую, без повторного proxy:
   это предотвращает цикл. В HTML сохраняются актуальные имена JS/CSS со сборки.
5. Django заменяет только метаданные и вставляет JSON для первого запуска React.
   После загрузки PageMetadata обновляет OG/canonical/robots при SPA-навигации;
   прежние title/description hooks продолжают работать. Старые запросы отменяются.

Внутренний fetch index имеет timeout 3 секунды и предел 2 MiB, не использует proxy
окружения и не следует редиректам. Адрес берётся только из конфигурации, не из
параметров посетителя. Index и HTML-ответы не кешируются: новый контент и запрет
публикации отражаются без пересборки и без очистки внутреннего кеша. При недоступном
или неверном index сервер отвечает 503 + Retry-After, а не успешной пустой страницей.

Frontend и backend теперь нужно обновлять совместно. Frontend production-image
для страниц требует работающий backend с этими маршрутами. Backend `/health/`
не зависит от frontend, поэтому зависимости запуска не образуют цикл.
Frontend healthcheck проверяет всю цепочку получения страницы.

`ALLOWED_HOSTS` production включает `backend` для внутреннего nginx proxy. Внутри
этой production-цепочки nginx устанавливает Host=backend и X-Forwarded-Proto=https;
внешний HTTPS завершает Caddy. Публичный origin берётся из FRONTEND_BASE_URL,
никогда не из пользовательского Host/X-Forwarded-Host.

## Адреса и совместимость

Динамические ссылки учитывают afisha: `/performance/:id` перенаправляется в
`/afisha/performance/:id`, пока запись в афише; после переноса — наоборот.
Для проектов аналогично `/projects/:id` и `/afisha/archive/:id`.
Старый `/archive/:id` перенаправляется на актуальную страницу проекта. Используется
302, чтобы смена статуса записи не застревала в permanent redirect браузера.
Трекинговые параметры не включаются в canonical. Неизвестный URL не перенаправляется
на главную. Отдельные сценарии физического удаления и последующего изменения
видимости не раскрывают прежние метаданные через кеш backend.

`GET /page-metadata/?path=/news/1` — публичный JSON для переходов внутри React.
Поле status описывает страницу (включая 404); сам JSON-запрос возвращает 200.
`/public-page/...` — внутренний маршрут HTML, также доступный на API-домене, но
все canonical указывают на основной сайт. Записи фильтруются по публичности.

В обычном CRA development nginx не участвует: React получает метаданные через API.
Для проверки именно исходного HTML нужна production-схема, либо отдельно запущенный
сервер готовой сборки, адрес index которого задан в PUBLIC_SPA_INDEX_URL.

## Развёртывание и внешняя проверка

1. Убедиться, что FRONTEND_BASE_URL — публичный origin сайта без пути; production
   Compose задаёт его и внутренний PUBLIC_SPA_INDEX_URL автоматически.
2. Пересобрать и обновить backend и frontend вместе обычной production-командой.
   Миграций БД в этом этапе нет; существующие тома/данные не меняются.
3. Проверить прямой URL опубликованной новости и спектакля через просмотр исходного
   HTML/curl: собственные og:title/image/url и canonical должны присутствовать без JS.
4. Проверить, что og:image открывается без авторизации из внешней сети. MinIO и его
   публичный домен должны быть доступны VK. Если постера нет, проверить logo512.png.
5. Проверить черновик/удалённую запись и неизвестный адрес: 404, noindex, без закрытых
   текста и изображений. Проверить редирект после переноса спектакля из афиши.
6. Отправить тестовую ссылку в VK/мессенджер. У сервисов собственный кеш карточек:
   ранее отправленная ссылка может обновиться не сразу, даже при корректном HTML.

Это серверные метатеги и canonical, **не полная серверная отрисовка содержимого**:
текст страницы внутри root по-прежнему рисует React. Пререндер/SSR основного контента
и JSON-LD остаются отдельными задачами. Гарантия поисковой позиции или немедленного
обновления стороннего кеша не следует из наличия Open Graph.

## Проверки реализации

- 166 backend-тестов прошли на Python 3.11/PostgreSQL, включая 13 новых проверок
  исходного HTML, видимости, экранирования, canonical и поведения при ошибке index.
- 36 релевантных frontend-тестов (9 наборов) прошли, в том числе отмена устаревшего
  ответа, обновление OG/canonical и noindex при SPA-навигации. Старые проблемные
  App/stringMatching suites не включались. TypeScript и production Docker build успешны.
- Отдельный Compose-проект с синтетической БД: настоящие nginx + Django + собранный
  React проверены Chromium с отключённым JS и обычным браузером. Прямые ссылки,
  отсутствие утечки черновика, реальный 404 и SPA-навигация работают. К production
  данным и реальному MinIO этот smoke test не подключался.
- Внешний робот VK и настоящие ссылки production проверяются после развёртывания.
