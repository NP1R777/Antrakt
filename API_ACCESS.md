# Права доступа к API

Роль администратора сайта определяется `is_superuser`; одного `is_staff` недостаточно.

| Данные / операция | Гость | Пользователь | Администратор |
| --- | --- | --- | --- |
| Публичные списки и карточки контента | Чтение | Чтение | Чтение |
| Создание, изменение, мягкое и полное удаление контента | Нет | Нет | Да |
| Списки `*-admin`, пользователи, модерация отзывов | Нет | Нет | Да |
| Даты рождения и варианты поздравлений в редакторе | Нет | Нет | Да |
| Поздравление на сегодня, выбранные отзывы и тексты сайта | Чтение | Чтение | Чтение и управление |
| Запуск импорта отзывов VK | Нет | Нет | Да |
| Профиль | Нет | Только свой | Любой |
| Отзывы под публичными карточками | Чтение | Создание, удаление своих, реакции | Также модерация |
| Загрузка изображений | Нет | Только аватар в собственной папке | Также изображения контента |
| Удаление файлов хранилища | Нет | Только собственная папка аватаров | Любой файл в настроенном хранилище |

Неавторизованный запрос к закрытой операции получает 401, запрос пользователя без
необходимой роли — 403. Удалённые карточки и неопубликованные новости, включая их
отзывы, возвращают посетителям 404. Администратор сохраняет доступ для редактирования
и восстановления. Удалённые отзывы не принимают новые реакции.

По умолчанию DRF использует `ReadOnlyOrSuperUser`. Публичные операции регистрации,
входа и восстановления доступа, а также пользовательские операции имеют собственные
разрешения. Новые административные списки нужно явно закрывать `IsSuperUser`:
проверка интерфейса React не заменяет проверку Django.

Профиль не позволяет обычному пользователю изменять роль, дату создания, `deleted_at`
или пароль. Для смены пароля предназначен отдельный API с проверкой текущего пароля.

Загрузка аватара использует `folder=profile`; сервер сам подставляет ID владельца:
`profile/<user_id>/<uuid>.<extension>`. Выбор чужой папки и фиксированного имени
пользователю запрещён. Удаление проверяет адрес настроенного хранилища и папку владельца.
Старые файлы не перемещаются: снятие аватара в интерфейсе отвязывает его от профиля,
не удаляя файл. Сохранение профиля обязательно для применения этого изменения.

Проверки прав и границ доступа находятся в `backend/app/my_app1/test_api_permissions.py`.
Запуск из `backend/app`:

```sh
USE_MINIO_STORAGE=False ../venv/bin/python manage.py test my_app1 --noinput
```

В тестах файловых операций S3 подменяется: они проверяют права, ключи объектов и
отсутствие вызовов хранилища при отказе. Это не интеграционная проверка MinIO.
Изменения не требуют миграции БД. Блокировка удалённых пользователей и новый
механизм восстановления пароля — отдельные следующие этапы.
