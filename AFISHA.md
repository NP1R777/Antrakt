# Карточки афиши и билеты по показам

## Ссылки

- Спектакль в афише: `/afisha/performance/<id>`.
- Мероприятие в афише: `/afisha/archive/<id>`.
- Постоянные карточки после переноса: `/performance/<id>` и `/projects/<id>`.

Карточка загружает запись из существующего API (`/perfomance<id>/` или `/archive<id>/`).
Параметр React location.state не нужен и не используется для данных карточки.
Список афиши содержит настоящие ссылки: можно открыть в новой вкладке или скопировать.
Секция на главной тоже учитывает тип записи, включая совпадающие ID разных таблиц.

Старые `/performance/<id>` и `/projects/<id>` уже умели загружать данные по ID.
Теперь они перенаправляют в новую карточку афиши, если запись ещё в афише.
Если запись ушла из афиши, её адрес `/afisha/...` перенаправляет на постоянную
страницу. Это клиентские переходы React Router с replace, не HTTP-редиректы сервера.
`/archive/<id>` сохраняет прежнюю совместимость через `/projects/<id>`.

404 API и неправильный тип/ID показывают «Запись не найдена». Для сетевой ошибки
есть отдельное сообщение и повторный запрос. При смене адреса устаревший запрос
отменяется и не может подменить новую запись. Удалённые мероприятия исключены из
публичного списка афиши. Sitemap использует текущие адреса афиши или постоянных карточек.

## Билеты

Показы сортируются по дате; у каждого остаётся его собственная ссылка `shows[].ticket_url`.
Если она отсутствует, используется общая `ticket_url`, с подсказкой выбрать эту дату
на странице продажи. Если отсутствуют обе ссылки, кнопки нет. Ссылки открываются
в новой вкладке; допускаются только абсолютные HTTP/HTTPS-адреса.

Время показывается в Asia/Krasnoyarsk. Для уже начавшегося показа покупки через эту
страницу нет; время обновляется раз в минуту. Это не проверка наличия свободных мест:
продажей и доступностью билетов управляет внешняя площадка.
Если показов нет, общая ссылка остаётся доступна, а даты отмечены как уточняющиеся.
Для мероприятий отображается дата; отдельной модели билетов мероприятий сейчас нет.

Администратор уже может указать ссылку при добавлении показа в PerformancesForm;
нового обязательного поля не добавлено. Автоматический перенос спектаклей/проектов,
синхронизация ролей и настройки поэтапного перехода на FK не менялись.
Миграция базы для этой доработки не требуется.

## Проверки

Backend: `test_afisha_links.py` — прямое чтение, ID/ссылки показов, удалённые записи,
sitemap и существующий автоматический перенос. Frontend: `AfishaDetail.test.tsx`,
`ShowTickets.test.tsx` — прямые адреса, устаревшее state, повтор запроса, гонка ответов,
перенос в постоянный раздел, даты и запасные/недопустимые ссылки.
Проверка собранного приложения в Chromium использует подменённые ответы API;
реальная билетная площадка, покупка и оплата в неё не входят.
